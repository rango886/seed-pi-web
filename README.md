# seed-pi-web

给 [pi](https://pi.dev) coding agent 做的网页界面。界面风格是亮色的 Dear ImGui：直角、紧凑、等宽字体。

**用的是原版 pi，不用改它。** 后端只跑 `pi --mode rpc`，按文档里公开的 RPC 协议收发 JSON。pi 升级以后，一般不用跟着改。

## 用法

### 装成全局命令（推荐）

```bash
npm i -g seed-pi-web      # 发布以后
# 或者在项目目录里：npm install && npm run build && npm link

seed-pi-web start         # 后台启动，打印访问地址
seed-pi-web open          # 用浏览器打开（自动带 token）
seed-pi-web stop          # 关闭
```

| 命令 | 说明 |
|---|---|
| `seed-pi-web start [-f] [-o] [-p 端口] [--host 地址] [--token xxx]` | 默认后台运行；`-f` 前台运行（Ctrl+C 退出）；`-o` 启动后打开浏览器；参数只管这一次，不写进配置 |
| `seed-pi-web stop` / `restart` / `status` | 关闭 / 重启 / 看状态。关闭时让后端自己把 pi 进程和终端收拾干净，没反应才强杀整棵进程树 |
| `seed-pi-web logs [-f] [-n 行数]` | 看后台日志，`-f` 持续跟踪 |
| `seed-pi-web token` | 显示 token；`token set <值>` 设置、`token gen` 随机生成、`token clear` 去掉 |
| `seed-pi-web config` | 看全部配置和来源；`config get/set/unset <键>`、`config path` |

配置存在 `~/.seed-pi-web/config.json`，同一个目录里还有后台日志 `server.log` 和运行状态 `server.json`。改完配置要 `restart` 才生效。读取顺序：命令行参数 > 环境变量 > 配置文件 > 默认值。`npm start` 也会读这个配置文件。

后台启动时，pi 的工作目录（网页里默认打开的目录）就是你执行 `seed-pi-web start` 时所在的目录。

### 在项目里直接跑

```bash
npm install
npm run build     # 构建前端
npm start         # http://127.0.0.1:8787
```

开发模式：`npm run dev`，然后打开 http://localhost:5173 （前端会热更新，后端改了自动重启）。

前提：命令行里能直接运行 `pi`，而且已经登录好或配好模型。

## 能做什么

| 功能 | 怎么用 |
|---|---|
| 对话 | 回复是流式显示的；思考过程默认折叠，工具调用显示成卡片（edit 会画 diff，点路径能打开文件） |
| 运行中插话 | Enter = steer（当前这一步做完就插进去），Alt+Enter = follow-up（全部做完再发），Esc = 停止 |
| `/` 命令 | 输入 `/` 弹出菜单。内置命令由网页翻译成 RPC 调用；扩展命令、prompt 模板、skill 从 pi 动态获取 |
| `!命令` | 直接跑 shell，输出进上下文；`!!命令` 输出不进上下文 |
| 会话和进程 | 每个会话（jsonl 文件）有自己的 pi 进程，**按需启动**：点开会话只读会话文件显示历史，不起进程；模型目录和各模型的思考档位直接复用已安装 pi 的模块读取，不另起查询进程、不联网刷新、不缓存查询结果；默认设置合并全局及项目配置。打字、加附件、选择模型和思考档位都不起进程，选择暂存在当前页面，首次发送（或执行其他需要 pi 的操作）时再起 pi 并应用。修改配置后刷新页面即可重新读取。同一个目录里的几个会话可以同时跑；开新会话、切到别的会话，原来的在后台接着跑。「新会话」一键沿用当前目录；旁边的下拉箭头和输入框的目录按钮都按「当前 → 收藏 → 最近 → 浏览其他目录」选择目录。输入前换目录保留未发送的文字和附件，已有对话换目录则另开新会话。侧栏会话前面有状态图标：转圈 = 正在回复，实心点 = 有新回复没看，黄点 = 在等你操作，空心圈 = 别的窗口在用 |
| 多个窗口 | 同一个会话可以在好几个标签页/浏览器里打开，内容和吐字实时同步，中途打开的也能接上。第一个打开的窗口是操作者，其他窗口只能看，点「接管」可以把操作权拿过来；操作者关掉或离开 10 秒后自动放开 |
| 切换目录 | 点输入框下面的目录按钮，或者 `/cd`。会回到这个目录上次用的会话；顶栏的「进程」按钮可以看所有进程 |
| 历史 | 左侧栏就是会话列表；`/resume` 或 Ctrl+P 打开会话选择器。悬停会话时可归档 / 取消归档（在删除按钮左边），右键菜单也能操作；归档不删除文件、不停止任务、不关闭当前聊天，提示里可以撤销。搜索栏的「显示」下拉可筛选未归档 / 已归档 / 全部，默认仅未归档，并可设置消息条数、更新时间以及平铺列表中路径的显隐；「全部 / 当前目录 / 收藏」各自记住排序和显示设置，「全部 / 收藏」还可选择平铺 / 按目录折叠、文件夹名称 / 完整路径。归档状态保存在服务端 `~/.seed-pi-web/session-archive.json`（随 `SEED_PI_WEB_HOME` 改变），多窗口同步；显示偏好保存在浏览器本地 |
| 文件 | 顶栏「文件」按钮（Ctrl+E）打开右侧浮动的文件树；更改列表和文件树之间可上下拖动分隔条，自动记住比例，双击恢复默认。点开的文件在顶部标签页里，带语法高亮，Markdown 可以预览；AI 改了文件会自动刷新；点 `@` 可以把文件路径引用到输入框 |
| Git | 文件侧栏显示所属仓库的分支和变更；按「合并更改 / 暂存的更改 / 更改」分组，支持列表 / 树形切换，文件树显示状态、目录汇总圆点和忽略状态。点击变更打开只读对比，可切换并排 / 合并显示，窄屏自动合并；已暂存、未暂存、全部变更各自使用独立标签。后端调用本机 Git CLI，不执行提交、暂存或回滚 |
| 下载 | 文件树右键下载文件或目录，顶部工作目录右键可下载整个目录。目录生成 ZIP，包含当前磁盘内容（含未提交 / 被忽略文件），始终排除 `.git`、跳过符号链接；可选择排除依赖目录。单次最多 1GB / 20000 条目，打包超时 2 分钟，临时 ZIP 下载后清理，未下载的 10 分钟过期 |
| 终端 | Ctrl+\` 或顶栏按钮打开，和文件一样是顶部的标签页；是真正的 shell（node-pty），刷新页面以后终端还在。标签栏右边有「关闭全部」，标签上右键可以关闭其他 |
| 状态信息 | 花费、缓存命中、tokens、上下文默认收起，点输入框里思考强度右边的按钮（或右键菜单）展开 |
| 图片 | 在输入框里粘贴或拖进来 |
| Markdown | 表格、任务列表、代码高亮（带复制按钮）；公式 `$…$` / `$$…$$` 用 Temml 转成 MathML 交给浏览器排（不下载字体）；` ```mermaid ` 代码块画成图（pele，按图类型按需加载，配色跟界面主题走；图比窗口宽时右下角有放大/缩小/还原，Ctrl+滚轮和双击也能缩放，放大后可以拖；右下角「源码/图示」切到源码，复制按钮跟普通代码块一样在右上角；图里的标签少写了引号会先自动补上再画，实在画不出来就把原因和源码摆出来）；图片写本地路径也能显示（相对当前目录的，或者 `C:/Users/…` 这种绝对路径，都走后端读文件；文件预览里的相对图片按文件所在目录找），高度有上限、按原比例缩，点一下全屏看大图，左右按钮（或方向键）翻这个会话里的其它图片 |
| 扩展 UI | select/confirm/input/editor 弹窗，以及 notify、状态栏、widget、标题都支持 |

### 斜杠命令是怎么对应的

- 下面这些在网页里直接能用（翻译成对应的 RPC 命令）：`/new` `/resume` `/model` `/thinking` `/name` `/compact` `/fork` `/clone` `/session` `/copy` `/export` `/reload`（重启 pi 进程，会话保留）`/quit`。还有网页自己加的 `/cd` `/terminal` `/hotkeys`
- `get_commands` 返回的命令（扩展、模板、skill）原样发给 pi
- `/settings` `/login` `/logout` `/scoped-models` `/tree` 等只有终端界面才有，网页会在下方终端里打开一个真正的 `pi` 让你操作。改完回到网页输入 `/reload` 就生效
- 不认识的 `/xxx` 和终端版一样，当普通文字发出去

## 结构

```
浏览器 (Vue)  ──WebSocket──  server/index.js  ──stdin/stdout JSONL──  pi --mode rpc（每个会话一个）
                │                 │
                └──HTTP──  文件 / 历史会话接口      node-pty ── 终端
```

- `server/pi-agent.js`：管一个 pi 子进程。按 LF 切分 JSONL，把请求和回复按 id 对上；还会缓存没回复的扩展弹窗、扩展状态，以及“进行中”的事件（正在吐的字、正在跑的工具），刷新页面、中途打开的窗口都能接上
- `server/index.js`：HTTP 和 WebSocket。按会话文件管理 pi 进程和操作权。RPC 命令**原样转发**，所以 pi 以后加了新命令，后端不用改。新会话先不起进程，第一次要用时再起；fork/clone 以后进程跟着去新文件，只是在看旧会话的窗口退回只看旧文件
- `server/git.js`：只读 Git CLI 查询、porcelain v2 状态解析、提交 / 暂存区 / 工作区文本对比；不运行外部 diff 或 textconv。变更列表覆盖当前目录所属的整个仓库，文件树仍从当前目录展开；文本对比上限 2MB，二进制和子模块内部变化只给提示，冲突比较 ours 与工作区，不是三方合并编辑器
- `server/downloads.js`：目录 ZIP 生成、临时文件过期清理和一次性流式下载
- `web/src/git.js`：共用 Git 状态与文件树装饰索引；打开侧栏、工具改文件、切目录、页面重新获得焦点时刷新，可见且使用文件功能时每 5 秒检查状态
- `server/sessions.js`：读 `~/.pi/agent/sessions/**/*.jsonl` 生成历史列表（只读 header、名称和第一条消息）
- `web/src/store.js`：前端的全部状态和逻辑，包括事件处理、斜杠命令映射、扩展 UI
- `web/src/components/*`：只管显示

### 为什么 pi 升级基本不用改

1. 只用文档里公开的东西：RPC 命令和事件、会话文件格式、CLI 参数
2. 扩展、模板、skill 命令用 `get_commands` 动态获取，不写死
3. 认不出的事件直接忽略；认不出的消息类型折叠起来显示原始 JSON；认不出的工具用通用卡片显示
4. 每次都通过 `pi` 命令启动，跟着你装的版本走

唯一要手动维护的是 `store.js` 里的 `BUILTINS` / `TUI_ONLY` 两张表，也就是 pi 内置终端命令的对应关系。这部分很少变。

## 配置

可以用 `seed-pi-web config set <键> <值>` 写进配置文件，也可以用环境变量（环境变量优先）。

| 配置键 | 环境变量 | 默认值 | 说明 |
|---|---|---|---|
| `port` | `PORT` | 8787 | 端口 |
| `host` | `HOST` | 127.0.0.1 | 监听地址 |
| `token` | `SEED_PI_WEB_TOKEN` | 空 | 设置后访问要带 `?token=xxx`（只用第一次，之后存在浏览器里）。监听非本机地址时一定要设 |
| `piBin` | `SEED_PI_WEB_PI_BIN` | `pi` | pi 可执行文件 |
| `piArgs` | `SEED_PI_WEB_PI_ARGS` | 空 | 额外传给 pi 的参数，比如 `--provider anthropic`，也可以写 JSON 数组 |
| `shell` | `SEED_PI_WEB_SHELL` | pwsh / $SHELL | 终端用的 shell |
| `idleMinutes` | `SEED_PI_WEB_IDLE_MINUTES` | 30 | 空闲的 pi 进程过多久自动关掉（开着页面看也算空闲，关掉后页面退回只看，再打字会重新起；一句话没说的新会话 2 分钟就关） |

另外 `SEED_PI_WEB_HOME` 可以换掉 `~/.seed-pi-web` 这个目录。

### 局域网访问（手机、别的电脑打开）

默认只监听 `127.0.0.1`，本机以外连不进来。要让局域网里别的设备用，两件事得一起做：监听所有网卡 + 设一个 token。

```bash
# 写进配置，以后每次启动都生效
seed-pi-web config set host 0.0.0.0
seed-pi-web token gen
seed-pi-web restart
```

只想临时开一次，也可以用环境变量：

```bash
# bash / zsh
HOST=0.0.0.0 SEED_PI_WEB_TOKEN='自己编一串够长的' npm start
```

```powershell
# PowerShell：先设环境变量再启动
$env:HOST='0.0.0.0'; $env:SEED_PI_WEB_TOKEN='自己编一串够长的'; npm start
```

启动日志会打印带 token 的地址（`http://localhost:8787/?token=...`），把它换成这台机器的局域网 IP，就能在手机或别的电脑上打开。token 只在地址栏用一次，前端会存进 localStorage 并把参数从地址栏抹掉，之后 `/api` 请求和 WebSocket 连接自动带上；脚本调用也可以直接用 `X-Seed-Pi-Web-Token` 头传。

关于这道锁，几件事得说清楚：

- **token 是唯一的一道锁**：一个大家共用的明文串，没有账号、没有权限分级、没有过期时间。要换就 `seed-pi-web token gen` 再 `restart`。
- **没设 token 时那道校验不是认证**：没有 token 时只接受 `Host` 是 `localhost` / `127.0.0.1` / `[::1]` 的请求，目的是防 DNS rebinding（外面的网站把域名解析到 127.0.0.1 来打你的服务）。`Host` 头是客户端自己填的，手写个 HTTP 请求就能绕过，所以不设 token 又监听 `0.0.0.0`，等于没锁。
- **HTTP 是明文的**：`?token=` 可能留在浏览器历史和中间设备的日志里，同一个 Wi-Fi 上抓包也能看到。长期用就套一层 HTTPS 反向代理，或者干脆用 Tailscale / SSH 端口转发，别把它直接暴露到局域网。
- **拿到 token 就等于拿到这台机器的 shell**：agent 能执行任意命令，网页里还有真终端，按 root 的权限对待。
- 校验范围：`/api/*` 和 `/ws` 才走 token；页面本身的静态文件不校验（所以不带 token 也能看到界面，但连不上后端）；剪贴板相关接口另外要求请求来自本机（loopback）。

## 测试

```bash
npm test          # 状态解析、暂存/未暂存对比、冲突、worktree、标签页、目录 ZIP 与下载接口
npm run build
```

Git 测试会在系统临时目录里创建独立仓库，不会暂存或提交当前项目。

## 注意

- 这是一个能执行任意命令的网页，默认只监听本机。要远程用，见上面的「局域网访问」：设 `SEED_PI_WEB_TOKEN`，再套 HTTPS 或 Tailscale
- 同一个会话不要同时在终端版 pi 和网页里打开，两个进程一起写同一个会话文件会冲突
- Linux 上 node-pty 需要编译：先装好 `build-essential` 和 `python3`，然后运行 `npm approve-scripts node-pty && npm rebuild node-pty`。装不上也没关系，只是终端功能不能用
